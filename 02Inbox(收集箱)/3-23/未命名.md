| Models+Datasets | 验证完整性→递归遍历配置目录加载→应用dataset_num_runs→加速器转换 | 121-211行 |
| HuggingFace模式 | 选择模型类(Chat/Base)→构建动态模型config→组装run_cfg | 188-208行 |
| Summarizer | 独立加载，支持`/`分隔符指定键名 | 213-239行 |


**算法**：遍历每个模型→过滤已完成任务（幂等性）→按n个一组分割数据集→生成任务列表

### NumWorkerPartitioner — 按worker数均衡

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `num_worker` | 8 | worker并发数 |
| `num_split` | None | 单个数据集分割数（默认=num_worker） |
| `min_task_size` | 16 | 最小任务数据量（小于此值不分割） |
| `strategy` | 'heuristic' | 'heuristic'（轮询分配到buckets）或 'split'（每个分割独立任务） |

**核心逻辑**：
1. 获取数据集大小（带缓存 `.cache/dataset_size.json`）
2. 大数据集按 num_split 分割（通过修改 `reader_cfg.test_range` 实现逻辑分割）
3. 按策略分配到 num_worker 个 bucket

**分割机制**：通过 `test_range` 组合实现，如原范围 `[10:100]` 再分割为 `[10:100][0:20]`

**成本计算**：

- PPL/MCQ任务：样本数 × 标签数（如4选项=×4）
- 特殊数据集（bbh*/math*）：额外 ×10

**算法**：按成本倒序排列 → 贪心装箱（当前桶+下一个超过max_task_size时新建桶）

### Subjective 系列 — 主观评估扩展

|------|------|------|

| `launch(tasks)` | List[Dict] → List[Tuple[str, int]] | **抽象方法**，返回 (task_name, exit_code) 列表 |

### LocalRunner — GPU 分配策略

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_num_workers` | 16 | 最大并发线程数 |
| `max_workers_per_gpu` | 1 | 每个GPU最多分配的工作线程 |

**GPU 分配核心数据结构**：
```python
gpus = np.zeros(max(all_gpu_ids) + 1, dtype=np.uint)  # GPU可用计数数组
gpus[all_gpu_ids] = max_workers_per_gpu                 # 初始化
```

**GPU获取流程**：`threading.Lock()` 保证线程安全 → 轮询等待可用GPU → 分配后递减计数 → 任务完成后递增释放

**调试模式 vs 正常模式**：
- **调试**：串行执行，支持模型复用（同一模型只加载一次）
- **正常**：ThreadPoolExecutor 并行，每个任务 UUID 参数文件 → subprocess.run(cmd)

**平台适配**：NPU(ASCEND_RT_VISIBLE_DEVICES) / Windows(set + &) / Linux(环境变量)

### SlurmRunner — 集群重试机制

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `retry` | 2 | 失败重试次数 |
| `partition` | None | SLURM分区 |
| `quotatype` | None | 配额类型 |
| `extra_command` | None | 额外srun参数 |

**失败判断（双重检查）**：`return_code != 0` **或** 输出文件不存在 — 防止SLURM返回码为0但文件未生成的情况

**重试策略**：失败 → 随机延迟(0-10s) → 重新生成命令（刷新端口号） → 再次执行

### DLCRunner — 阿里云作业监控

**环境配置**：支持三种Python环境（用户Conda / 公共Conda / 系统Python），自动配置 HF_HUB_CACHE、TORCH_HOME、代理等环境变量

**作业监控循环**：定期 dlc get job 查询状态 → 处理Pod时间与本地时间差 → 增量日志拉取 → Failed/Stopped返回-1，Succeeded返回0

**启动重试**：解析 job_id 失败时最多重试5次

### LocalAPIRunner — 信号量并发控制

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `concurrent_users` | 必需 | 最大并发请求数（Semaphore大小） |

**猴子补丁机制**：替换 `OpenICLInferTask.run()` → 将信号量注入到 `model.tokens` 属性 → API调用时自动acquire/release控制并发

**run() 执行流程**：
1. 遍历 model_cfg + dataset_cfgs 对

3. build_model_from_cfg() 构建模型

2. `_load_predictions()`：加载预测JSON（支持分割文件合并 `_0.json, _1.json, ...`）
3. `_process_predictions()`：三步后处理
   - 角色提取：`extract_role_pred()` 提取指定角色输出
   - 模型级后处理：`model_cfg['pred_postprocessor']`
   - 数据集级后处理：`eval_cfg['pred_postprocessor']`
4. `_evaluate_predictions()`：
   - 动态参数过滤（`inspect.signature` 只传递 `evaluator.score()` 需要的参数）
   - 调用 `evaluator.evaluate(k, n, test_set, **preds)`
5. 保存结果 + 可选 dump_details

| `encode(prompt)` / `decode(tokens)` | Tensor / str | 编码/解码 |
| `get_token_len(prompt)` | int | token长度 |

**模板方法**（已实现）：`generate_from_template()`, `get_ppl_from_template()`, `parse_template()` — 先通过 template_parser 解析模板，再调用抽象方法

**LMTemplateParser**：将 PromptList 按 meta_template 的 round/begin/end 配置生成最终字符串。`mode='gen'` 时遇到 `generate=True` 的 role 停止；`mode='ppl'` 时完整解析

### BaseAPIModel（API模型基类）

继承 BaseModel，`is_api=True`

**新增参数**：query_per_second(QPS限流), retry(重试次数), verbose

**TokenBucket 限流机制**：
- 后台 daemon 线程每 `1/rate` 秒释放一个 Semaphore token
- API 调用前 `acquire()` 阻塞等待可用 token
- 实现精确的 QPS 控制

**APITemplateParser** vs **LMTemplateParser**：

| 特性 | LMTemplateParser | APITemplateParser |
|------|-----------------|-------------------|
| 输出格式 | 纯文本字符串 | PromptList（role+prompt对象列表） |
| Role处理 | 自定义role标记 | 标准OpenAI格式（system/user/assistant） |
| 应用场景 | 本地模型推理 | API调用 |

### 参数分离机制

**关键设计**：`build_model_from_cfg()` 在构建模型前移除运行时参数

```
Config层: {type, path, max_out_len, batch_size, generation_kwargs, meta_template, ...}
    ↓ build_model_from_cfg() 移除 max_out_len/batch_size/min_out_len/run_cfg/abbr
模型层: ModelClass.__init__(path, generation_kwargs, meta_template, ...)
    ↓ Inferencer接收分离出的参数
推理层: GenInferencer(model, max_out_len=512, batch_size=8)
    ↓ 推理时传递
调用: model.generate(inputs, max_out_len=512)
```

### 代表性实现

**HuggingFacewithChatTemplate**：支持 batch_padding、mid截断模式（保留前后各一半）、PEFT微调权重加载

**VLLM**：通过 SamplingParams 配置生成参数，PPL计算使用 prompt_logprobs 特性

**OpenAI**：ThreadPoolExecutor 并发调用 → TokenBucket 限流 → 多key轮询（invalid_keys跳过） → 重试机制

**Qwen**：DashScope SDK封装，支持 disable_data_inspection 禁用内容审查

### 核心方法链

**1. `_pick_up_results()`** — 结果收集

从 `work_dir/results/{model}/{dataset}/` 读取所有JSON，返回：
- `raw_results`：{model: {dataset: result_dict}}
- `parsed_results`：{model: {dataset: {metric: score}}}（仅数值，排除METRIC_BLACKLIST）
- `dataset_metrics`：{dataset: [metrics]}（按METRIC_WHITELIST优先级排序）
- `dataset_eval_mode`：{dataset: 'gen'|'ppl'|'ll'}

**METRIC_WHITELIST 优先级**：score > auc_score > accuracy > humaneval_pass@1 > rouge1 > f1 > exact_match > extract_rate

**2. `_calculate_group_metrics()`** — 五种聚合策略

| 聚合方法 | 触发条件 | 公式 |
|---------|---------|------|
| **weighted_average** | `'weights' in sg` | Σ(score×weight) / Σ(weight) |
| **harmonic_mean** | `sg.get('harmonic_mean')=True` | n / Σ(1/score) |
| **standard_deviation** | `sg.get('std')=True` | sqrt(Σ(score-mean)²/n) |
| **sum** | `sg.get('sum')=True` | Σ(score) |
| **naive_average** | 默认 | Σ(score) / n |

**3. `_format_table()`** — 表格格式化

生成二维表格：`[['dataset','version','metric','mode','model-A','model-B'], ...]`

支持 `required_dataset_abbrs` 指定显示顺序，智能选择默认指标（优先级最高的）

**4. `summarize()`** — 完整流程

`_pick_up_results()` → `_calculate_group_metrics()` → `_format_table()` → 屏幕输出 → `_output_to_file()` → 可选Lark通知

**5. `_output_to_file()`** — 三种输出格式

| 格式 | 文件名 | 用途 |
|------|--------|------|
| TXT | `summary_{time}.txt` | 包含tabulate/csv/markdown/raw四种展示（分隔符隔开） |
| CSV | `summary_{time}.csv` | 导入Excel/Python分析 |
