根据您上传的论文《Causal Evaluation of Language Models》，**Adaptation（适应）** 是 CaLM 框架的四个核心模块之一。这一部分主要探讨如何将通用的语言模型“适应”到具体的因果推理任务中。在本文中，这种适应主要通过 **Prompt Engineering（提示工程）** 来实现 。

以下是关于该论文中 Adaptation 和 Prompt Engineering 部分的详细解读：

### 1. 核心概念：什么是 Adaptation？

在 CaLM 框架中，Adaptation 指的是通过引入额外数据或指令，将预训练的通用语言模型转化为能够解决特定因果任务的模型的过程 。
虽然适应的方法包括微调（Finetuning）等，但这篇论文**专注于 Prompting（提示）**，因为这是应用语言模型进行因果推理最直观、最常用的方法 。

### 2. 提示工程分类体系 (Taxonomy)

论文首先在宏观层面定义了一个广泛的提示工程分类空间，包括以下几种类型 ：

* **Basic Prompt (基础提示)**：直接陈述问题，不提供示例。
* **Adversarial Prompt (对抗性提示)**：用于测试鲁棒性，包括提示攻击、提示注入和越狱。
* **In-context Learning (IcL, 上下文学习)**：提供背景知识或示例（0-shot, Few-shot）。
* **X-of-Thought (思维链等)**：如 Chain-of-Thought (CoT)，鼓励模型展示推理过程。
* **Self-Consistency (自洽性)**：对多个输出进行采样并选择最佳结果。
* **Instruction Prompt (指令提示)**：只提供任务指令而不提供具体示例（解决了上下文长度限制问题）。
* **Iterative Prompt (迭代提示)**：通过多轮交互引导模型。
* **External Tool Use (外部工具使用)**：如 RAG（检索增强生成）。

### 3. 具体实施 (Concrete Implementation)

为了进行标准化评估，CaLM 从上述分类中筛选并实施了 **5 大类、共 9 种** 具体的提示策略。选择这些策略是基于受众广泛性、模型鲁棒性测试、用户友好性和实验可控性 。

这 9 种策略如下：

#### (1) 

Basic Prompt (基础提示) 

* **定义**：直接将问题作为输入，不提供任何示例或额外指令。
* **目的**：作为**基线 (Baseline)**，展示模型在最原始状态下的表现，用于与其他高级提示策略进行对比。

#### (2) 

Adversarial Prompt (对抗性提示) 

为了评估模型的**鲁棒性**（即面对干扰时能否坚持正确答案），设计了两种对抗形式：

* **Adversarial-ignore (对抗-忽略)**：
* 流程：模型给出答案 -> 提示模型“忽略你之前的答案，重新回答” -> 观察模型是否改变立场。


* **Adversarial-doubt (对抗-质疑)**：
* 流程：模型给出答案 -> 提示模型“你之前的答案是错的，请重新回答” -> 观察模型是否盲目修改答案。
* 
发现：模型往往倾向于修改原本正确的答案，而不是坚持己见 。





#### (3) 

Chain-of-Thought (CoT, 思维链) 

旨在增强模型解决复杂推理问题的能力。

* **0-shot CoT**：在提示中加入简单的触发词，如 "Let's think step by step"（让我们一步步思考），不提供示例。
* **Manual CoT (人工 CoT)**：提供包含详细推理步骤的人工编写示例（Few-shot）。
* 
发现：Manual CoT 对于 GPT-4 等顶级模型非常有效，能显著提升在复杂反事实任务上的表现 。





#### (4) 

In-context Learning (IcL, 上下文学习) 

通过提供示例让模型学习任务模式。

* **0-shot IcL**：只提供任务背景描述，无示例。
* **1-shot IcL**：提供 1 个示例。
* **3-shot IcL**：提供 3 个示例。
* 
发现：通常 3-shot IcL 能显著提升性能，但在某些数学计算任务中，增加示例数量可能效果更佳 。





#### (5) 

Explicit Function (EF, 显式功能/角色扮演) 

* **定义**：通过指令赋予模型特定角色或功能设定。例如：“You are a helpful assistant for causal reasoning...”（你是一个因果推理助手...）。
* **目的**：测试这种简单的指令（Instruction Prompt）是否能在不增加大量 token 的情况下提升表现。

### 4. 关键实验结论 (Empirical Findings on Adaptation)

基于上述策略，论文得出了多项关于 Prompt Engineering 的重要发现：

* 
**没有“万能提示”**：不同的因果场景需要不同的最佳提示。例如，低阶因果任务（关联）适合用 1/3-shot IcL，而高阶反事实任务更适合 Manual CoT 。


* 
**复杂任务需要更多引导**：在复杂的因果场景中，简单的提示（如 Basic）效果不佳，必须使用 Manual CoT 来激发模型的推理能力 。


* 
**对示例数量敏感**：模型对 IcL 的示例数量（Shot number）非常敏感，从 1-shot 到 3-shot 可能会带来显著的性能变化 。


* 
**Prompt 之间的相关性**：Basic Prompt 与 EF、0-shot CoT、0-shot IcL 的表现高度相关（因为它们本质都很简单），但与 3-shot IcL 和 Manual CoT 的相关性较弱（说明后者真正改变了模型的推理模式）。



总结来说，这一部分不仅建立了一个提示工程的分类学，还通过大量实验证明了**针对特定因果任务选择合适 Prompt 的重要性**，特别是 **Few-shot (IcL)** 和 **CoT** 在提升复杂推理能力方面的关键作用。
